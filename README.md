# 身体记录看板

在自己的电脑上记录身体变化、饮食与训练。三栏看板、统一打卡日历、中文食物库、训练成长反馈和开发者批注均可本机使用。

**分享代码不会分享账本。** 每份安装使用自己电脑上的独立数据库。仓库包含应用代码、公开食品数据与插图，首次启动时身体记录、饮食、训练、计划、回收站、批注和个人资料均为空。

## 开始使用

**下载并解压代码，或用 Git 克隆后，双击项目文件夹里的启动文件：**

| 系统 | 双击文件 |
| --- | --- |
| macOS | `启动身体日记.command` |
| Windows | `启动身体日记.cmd` |

电脑需要 **Node.js 24 或更高版本**。启动文件会检查，未安装或版本太旧时打开 [Node.js 官方下载页](https://nodejs.org/en/download)。安装一次后，再次双击即可。

首次启动会自动安装依赖、创建本机配置和空白数据库，然后打开浏览器；需要联网并等待几分钟。以后双击直接启动，代码更新导致依赖变化时会自动重新安装；更新依赖前请先关闭旧的启动窗口。同一份安装已经运行时，会打开已有页面；默认端口被占用时自动选择其他本机端口。启动窗口会显示进度，失败时保留提示，处理后再次双击即可。

**使用期间保持启动窗口开启。** 按 Ctrl+C 停止服务，记录会保留；下次仍然双击同一文件。食品检索使用随代码提供的目录，正常记录无需模型连接。

第一次进入空白账本会出现可跳过的使用引导：填写个人资料、设置自己的饮食/训练目标，或连接 Captain。各项均可稍后完成，应用不会预填健康目标或自动启用 AI。已有资料、记录或计划时不自动打扰；“个人资料与备份 → 备份与引导”中的“重新查看使用引导”可再次打开。跳过状态作为当前浏览器的界面偏好保存，换浏览器或清理网站存储后，空白账本可能再次显示引导。

也可以继续使用命令行（需要 Git；直接下载代码的用户不需要安装 Git）：

```sh
git clone https://github.com/chiyubaima/body-metrics-dashboard.git
cd body-metrics-dashboard
npm ci
npm start
```

打开终端显示的本机地址，通常是 `http://127.0.0.1:3000`。命令行方式同样自动初始化并保留已有记录；如端口已占用，可运行 `npm run dev -- --port 3001`。Linux 用户可以使用这组命令。

三模块记录不需要 Codex、ChatGPT、Cloudflare 账号，也不需要 USDA 或模型 API 密钥。本机入口会自动建立一个仅用于本机的会话，不会登录作者的账号。首次安装依赖需要联网；食品查询使用仓库随附的数据，不调用翻译或识别服务。可选的 AI 教练需要模型连接，见下文。

## 可以记录什么

- **身体**：晨重均值、腰围、体脂、自动 BMI，30/90 天趋势和身体日记。
- **饮食**：13,225 项食品的完整中文名称、原始英文与营养参考；按份量计算热量和三大营养素，记录四个餐次，调整当前或历史日期的营养目标。
- **训练**：按目录选择抗阻动作，记录重量、组数及每组次数；一次有氧可以包含多个运动项目并自动合计时长；按部位展示可追溯的力量变化与成长形象。
- **日历与回收站**：统一显示三类记录，历史支持修改、多选删除与恢复。
- **开发者模式**：选择页面元素、保存批注并管理处理状态；批注仅存本机。
- **Captain**：结合三模块记录聊天，按时段主动问候，保存可编辑的偏好与约定，到期在页面内跟进。默认关闭，设置中核对服务后启用。

个人资料和目标由每个使用者自行填写。缺失数据不补零，不预装作者的记录或个人计划。食品数据来源与翻译说明见 [data/README.md](data/README.md)。营养值和训练力量值是记录参考，保留原始来源和估算口径。

## 连接 Captain

在日历右侧打开 Captain，点击聊天顶部的“设置”，直接选择连接方式：

- **Codex 登录**：使用当前 ChatGPT 账号和固定的 `gpt-6-astra`。已有登录会自动识别；未登录时点击“登录 ChatGPT”，在官方授权页完成后，设置页自动更新状态。
- **模型 API**：选择 Responses 或 Chat Completions 协议，填写 API 根地址、模型名称和密钥。点击“保存并切换连接”后立即生效，无需重启。

切换后核对当前服务、模型和数据发送范围，点击“启用 Captain”。API 配置会保留，切回时不必重填；密钥不回显，同一地址留空保留已有密钥，改用新地址必须填写对应密钥。本机免密服务可留空。本机配置只写入被 Git 忽略且禁止通过网页读取的 `.dev.vars.coach.json`，权限为仅当前用户可读写；首次兼容读取旧 `.dev.vars`。终端向导 `npm run coach:setup` 仍可使用，并写入同一份配置。

项目固定安装独立 Codex CLI，不更改全局 Codex。登录通过官方 app-server 的账号与浏览器授权接口完成，应用不读写或复制 Codex 凭据文件；登录依赖本机 Codex、联网和账号可用额度。官方说明：[Codex App Server 账号授权](https://learn.chatgpt.com/docs/app-server#authentication-modes)。

外部 API 地址要求 HTTPS，回环地址允许 HTTP。API 模型需要支持 SSE 流式和严格 JSON Schema 结构化输出；Responses 请求设置 `store: false`，这不等于服务商完全不留存处理日志，数据政策以所选服务为准。[结构化输出接口说明](https://developers.openai.com/api/docs/guides/structured-outputs)。

教练每次读取当前账本，提供近30天摘要、所选日和部分最近记录明细、可比力量参考、个人资料、最近最多12轮且有长度上限的聊天、已保存记忆与待办约定。历史回复下方的“参考了 N 条记录”保留当时引用的快照；后续分析使用更正后的记录。记忆与约定卡片由用户点击保存后生效，可在“记忆与约定”里修改或结束。

聊天中，Captain 会主动识别你明确说出的偏好、目标、临时安排和未来约定，在回复下方显示原话、提醒时间及有效期。点击“确认记住／确认约定”才生效，也可选择“暂不记录”。没有明确期限的记忆长期保留；“这周出差”等限时安排到期后失效，时间含糊时先追问。约定区分提醒和失效时间，默认在提醒当天结束（北京时间）后过期，也能编辑截止时间。

“记忆和约定”底部的“已过期/忘掉的记忆和约定”保留失效条目，可查看、调整后恢复或确认永久忘掉。恢复过期约定时需重选未来提醒时间；已完成约定另存完成历史。过期、忘掉的条目停止进入有效记忆和提醒，相关来源轮次不再传给模型。永久忘掉还会删除对应建议卡片的内容和原话，旧卡片不能重新保存；原聊天文字仍可查看。这不是对其他聊天中相似文字或模型服务商日志的全局删除。

有效期由本机服务在读取、聊天和前台检查时核对；网页关闭期间不运行后台任务，下次打开会先处理过期状态。活跃记忆、待办约定各限50条，历史归档不占活跃名额。

Captain 现在可以按需调用应用工具：按日期和关键词查询三类日记、复用看板口径计算与比较、检索食物和动作目录、整理身体/饮食/训练草稿、定位日记，以及核对和整理记忆/约定修改。聊天显示真实工具进度，完成后留下结果卡片。比如“比较最近两周晨重”“帮我记录今天早上80公斤”“查一下蛋白质和抗阻训练的研究”。支持“今天午餐跟昨天完全一样”：从已有记录引用指定餐次，保留当天其他食物。连续对话补充信息可引用近24小时内的用户原话，无需把整条记录重说一遍。缺少克数、测量条件或组数且没有明确来源时会追问；普通手动食物的未知营养仍留空；找不到目录的菜品可使用下述配方估算流程。

身体、饮食、训练草稿直接在 Captain 对话卡片展示日期与内容，点击「确认记录」即可保存，保持聊天和输入框不变并同步看板；需要调整时再点击「调整内容」打开原编辑器。工具调用本身不会保存。确认后卡片持久显示「已记录」；日记和确认状态一起提交，重复点击、网络中断后重试不会重复写入，也不会覆盖后续更正或恢复已删除记录。饮食新增默认追加到当天餐盘，保留原有食物；确认时重新核对来源和目标版本，原条目已修改或删除时保留草稿并提示重新整理。记忆和约定修改仍在管理编辑器确认。已忘掉的条目默认不进入工具查询；明确要求查看归档时才查询，永久忘掉也会清除工具卡片里的修改内容。

**菜品会越记越顺手。** Captain 先查本人的「自建菜品」，没有匹配再查随代码提供的 USDA 食物库；找到相符 USDA 条目时使用目录营养。两边都没有合适菜品时，由当前连接的模型分析原料（含油和调味料）、烹饪方式、参考份量、热量和三大营养素，在聊天卡片标为 **AI估算**。展开「配方与营养」可核对本次营养、原料和做法；「估算说明与营养口径」保留份量假设与每100g参考，点击「确认菜品并记录」后，菜品和本次饮食一起保存；未确认不会建库。

例如「午餐吃了一份香菇豆腐煲，帮我记录」。如果需要估算，卡片会写清参考一份约多少克；实际份量可调整，或在聊天里补充配方后重新整理。库内营养统一为每100g，按本次克数确定性换算；按份数换算的克重也标为估算。USDA 仅有相近原料时，不把它冒充相同菜品。

饮食记录窗口提供并列的 **自建菜品 / USDA 食物库**，另保留「最近吃过」。列表只负责选择和添加本次饮食。完整配方与管理放在「个人资料与备份 → 自建菜品」：可搜索，查看原料、做法、参考份量、营养、估算说明与保存时间，并确认移出库；之后 Captain 优先复用仍在库中的已确认配方，无需重新分析。历史饮食保留当时的配方与营养快照，移出库不改日记或本餐已选食物。同名冲突、保存失败时菜品、日记与聊天回执一起回退；确认重试不重复建菜品。自建库按账户隔离，随账本保存在本机数据库，不改 USDA 公开目录；正常查库和确认保存不调用模型。

有来源的知识查询使用 [Europe PMC 公开文献服务](https://europepmc.org/RestfulWebService)，不需要额外密钥。应用只向固定服务发送程序维护的通用主题词（如蛋白质、抗阻、睡眠、恢复），不发送姓名、健康数字或聊天原文；查询到的摘要会交给已选择的模型用于回答。默认以健康成人关键词筛选，主题首词检索标题，可按问题切换老年人或不限人群；仍需核对实际研究对象。当前每次最多读取4篇相关综述、荟萃分析或指南摘要，卡片显示实际标题、年份、出版物、PubMed 链接与摘要。它不是任意网页搜索，不覆盖所有问题，也不代表读取全文或完成系统性证据评估。无结果、连接失败或没有可核对引用时会明确反馈。

工具通过同一结构化输出适配 Codex、Responses 和 Chat Completions，应用负责执行。每次聊天最多3轮工具、6次调用和4次模型生成，共用120秒等待上限；每次检索限制结果大小，避免循环查询。主动问候不调用工具。引用验证保证来源 ID 来自本轮实际结果，不能保证模型对研究的每一句解释都正确。图片录入、自动改目标、外部日历和离线通知未包含在这一版中。

Captain 使用黑白灰聊天界面，角色采用深蓝运动服、红色点缀、白色星徽和自然肤色的彩色形象。桌面与日历按 1:2 并排，窄屏上下排列。顶部是静态头像，日历旁的形象按时段举哑铃、吃饭、休息，回复时思考；这些是角色动作，不代表用户已经完成活动。减少动态效果时只显示静态形象。聊天顶部有独立的“记忆和约定”“设置”入口。发送后立即显示消息并清空该条输入；等待回复时可继续写下一句，失败可在原消息旁重试。桌面 Enter 发送、Shift+Enter 换行，手机回车换行，中文输入法选词不会误发送。上翻阅读时新回复不抢位置；可点击“回到最新”，加载更早消息和收起后重开也会保留阅读位置。回复接收模型原生增量，正文逐步出现。只有完整输出通过校验并保存后，才显示记录依据、复制和可保存的提议；断流会保留未完成文字并提示原地重试。上方头像保持静态。

提醒目前在站内运行：前台约每30秒检查一次，回到页面时补查；关闭网页或停止服务期间不能准时推送，下次打开继续。主动问候按北京时间10、14、18、22点四个时段更新，每次读取最新上下文，服务端按本人和时段去重；重新打开只补最近已到的时段，次日10点前不新生成。问候要求含标点不超过60字，入口预览最多60个可见字符、三行，超出显示省略号；聊天保留全文。支持“今天安静”。记忆、约定和设置从标题栏的独立入口进入，返回聊天保留草稿及阅读位置。身体/饮食/训练约定按当天记录匹配完成；具体动作、时长、次数等复杂约定选择“聊聊近况”，由用户确认。关闭 AI 聊天不会删除记录、记忆或约定。

本机桥接只在开发服务运行时启动，监听回环地址并使用每次启动随机生成的内部凭据。桥接使用官方 `codex app-server --stdio` 协议，创建 `ephemeral` 临时会话、覆盖系统与开发者指令，禁用项目指令、已发现的 Skills/MCP、命令、浏览器、插件等原生工具；应用工具由看板服务端单独执行；独立临时目录在完成后清理。不读取或复制 Codex 登录凭证。部署产物不包含该本机桥接，后续线上运行需要单独配置 API 服务。

## 数据在哪里

| 内容 | 存放位置 | 是否进入 Git |
| --- | --- | --- |
| 记录、个人资料、计划、回收站、批注、教练聊天/记忆/约定 | `.wrangler/state/v3/d1/` | 否 |
| 本机 Sites 配置 | `.openai/hosting.json` | 否 |
| 环境变量和密钥 | `.env*`、`.dev.vars*` | 否 |
| 启动锁、运行实例和依赖指纹 | `.wrangler/launcher*`、`.wrangler/local-server.json` | 否 |
| 导出的账本备份 | 浏览器下载目录，或本机 `backups/` | 否 |
| 公开食品与中文译名 | `data/` | 是 |
| 程序、数据库结构、插图 | `app/`、`lib/`、`db/`、`drizzle/`、`public/` | 是 |

刷新、关闭网页、停止服务或更新代码不会删除账本。**不要删除 `.wrangler/`，也不要把整个项目文件夹（含隐藏文件）打包给别人。** 通过 GitHub 分享仓库即可；别人克隆代码不会连接你的电脑或数据库。

数据目录长期由 `.gitignore` 排除，日常提交和推送无需清理记录。`npm ci` 或 `npm run setup` 会为本仓库启用自动检查：提交前检查暂存文件，推送前检查待上传的提交历史；误加入数据库、备份、本机绑定或常见密钥时会停止操作，并保留本机文件。即使某个文件后来被删除，待上传的旧提交也会检查。已有自定义 Git hooks 时会保留原配置并提示手动检查，不覆盖其他工具。

在「个人资料与备份 → 备份与引导」中可以导出全部记录与计划，包括有效自建菜品、教练聊天、记忆和约定，备份内包含个人信息，请妥善保存。该导出不包含模型密钥或开发者批注；如需完整迁移本机数据库（包括批注），停止服务后备份整个 `.wrangler/state/`。当前没有页面导入备份的功能。删除项目文件夹前先备份本机数据库。

本机模式是**一份安装、一个账本**：不同电脑彼此独立，但能够直接操作同一电脑、同一项目目录或操作系统账号的人也可能访问该账本。开发服务只监听回环地址，不作为公网或多人共享服务器使用；不要用 `--host 0.0.0.0` 或网络隧道暴露它。GitHub 仓库公开不会自动部署网站或上传数据。

## 开发与验证

```sh
npm run dev           # 初始化并启动本机开发服务
npm run setup         # 幂等初始化，不覆盖已有配置或数据
npm run test          # 数据规则、账户隔离、计算和分享检查
npm run typecheck
npm run lint
npm run build
npm run check:share   # 检查 Git 暂存区中的待分享文件
npm run test:api      # 已启动本机服务时，创建并清理明确标记的临时测试记录
npm run test:coach:api # 教练鉴权、记忆、约定和备份接口；默认不调用模型
```

`test:api` 默认使用 3000 端口；设置 `BODY_DASHBOARD_TEST_URL=http://127.0.0.1:3001` 可验证另一份本机安装。测试只清理本次生成的 UUID 和专用标记，不删除普通记录。

`test:coach:api` 默认使用3001端口，可用相同环境变量覆盖。真实模型测试需在项目约定的空白 `work/coach-check` 副本执行，额外设置 `BODY_COACH_LIVE_MODEL=1`；脚本拒绝在原账本调用模型做测试。单元测试以隔离 SQLite 和模拟模型验证数据与并发规则。

研究查询另有 workerd 运行环境回归：执行真实查询模块，用合成响应验证来源解析与重定向拒绝，测试不连接外部文献服务。查询使用 Node 与 Cloudflare 均支持的手动重定向模式，非成功响应直接拒绝，不跟随到其他地址。

自动更新的常规测试使用临时 Git 仓库、合成账本和模拟启动程序；macOS/Linux 可另运行 `BODY_JOURNAL_UPDATE_RUNTIME=1 node --experimental-strip-types --test tests/update-runtime.test.ts`，验证真实服务的更新与确认重启。该检查只复制公开应用源码，使用空白数据库和本地测试远端，不连接模型或更新当前工作区，完成后清理测试副本。

代码使用 React、TypeScript、Vinext、SQLite/D1 和公开的 Sites 本机适配插件。数据库迁移只定义结构，不包含个人数据；新增迁移应追加，已应用的迁移不要改写。`AGENT.md` 约定开发和数据规则。

`.openai/hosting.example.json` 仅包含逻辑资源名。初始化会复制为被忽略的本机配置，已有配置不覆盖。本项目保留 Sites 构建能力；将来部署需要部署者自己的项目、账号和访问控制，与运行本机看板是两件事。

## 在页面内更新版本

通过 Git 克隆的本机安装会在打开页面、回到前台及每15分钟检查当前分支关联的 GitHub 分支。有新提交时，页面顶部“开发者模式”左侧出现 **更新版本**。点击后自动拉取代码并更新，期间显示进度。

只有说明文档变化时，更新立即完成。程序或依赖变化时，会先暂停热更新并弹出重启确认；点击 **稍后重启** 可以保留当前页面，顶部会继续显示 **重启完成更新**。保存各个页面中未提交的内容后，点击 **确认重启**：应用会停止本次启动的服务、按需安装依赖、执行数据库迁移，再使用原端口启动。服务恢复后页面自动刷新，已保存的记录和模型配置保留。准备依赖可能需要几分钟，请保持启动窗口开启和网络连接。

更新只允许安全的快进操作，不会自动提交、暂存或丢弃本机代码。遇到未提交改动、分支差异、网络故障或涉及本机数据路径的版本时，页面说明原因并提供重试。重启准备失败时保留待完成状态，可在原页面重试，或关闭启动窗口后重新启动；不会自动回退数据库。待完成状态只存于被忽略的 `.wrangler/update-state.json`。

直接下载 ZIP 的安装没有 Git 历史，无法使用自动更新；页面会给出说明。旧的启动窗口第一次接入此功能时，需要关闭后重新双击启动，或者重新运行 `npm start`。这项功能只在本机启动方式下提供，不用于远程部署。

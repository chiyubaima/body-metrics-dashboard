# 身体记录看板

在自己的电脑上记录身体变化、饮食与训练。三栏看板、统一打卡日历、中文食物库、训练成长反馈和开发者批注均可本机使用。

**分享代码不会分享账本。** 每份安装使用自己电脑上的独立数据库。仓库包含应用代码、公开食品数据与插图，首次启动时身体记录、饮食、训练、计划、回收站、批注和个人资料均为空。

## 开始使用

安装 **Node.js 24 LTS** 和 Git，然后运行：

```sh
git clone https://github.com/chiyubaima/body-metrics-dashboard.git
cd body-metrics-dashboard
npm ci
npm start
```

打开终端显示的本机地址，通常是 `http://127.0.0.1:3000`。首次启动会自动创建本机配置和数据库，以后启动会保留已有记录。端口已被占用时先关闭占用该端口的服务，或运行 `npm run dev -- --port 3001`。

不需要 Codex、ChatGPT、Cloudflare 账号，也不需要 USDA 或模型 API 密钥。本机入口会自动建立一个仅用于本机的会话，不会登录作者的账号。首次安装依赖需要联网；食品查询使用仓库随附的数据，不调用翻译或识别服务。

## 可以记录什么

- **身体**：晨重均值、腰围、体脂、自动 BMI，30/90 天趋势和身体日记。
- **饮食**：13,225 项食品的完整中文名称、原始英文与营养参考；按份量计算热量和三大营养素，记录四个餐次，调整当前或历史日期的营养目标。
- **训练**：按目录选择抗阻动作，记录重量、组数及每组次数；一次有氧可以包含多个运动项目并自动合计时长；按部位展示可追溯的力量变化与成长形象。
- **日历与回收站**：统一显示三类记录，历史支持修改、多选删除与恢复。
- **开发者模式**：选择页面元素、保存批注并管理处理状态；批注仅存本机。

个人资料和目标由每个使用者自行填写。缺失数据不补零，不预装作者的记录或个人计划。食品数据来源与翻译说明见 [data/README.md](data/README.md)。营养值和训练力量值是记录参考，保留原始来源和估算口径。

## 数据在哪里

| 内容 | 存放位置 | 是否进入 Git |
| --- | --- | --- |
| 记录、个人资料、计划、回收站、批注 | `.wrangler/state/v3/d1/` | 否 |
| 本机 Sites 配置 | `.openai/hosting.json` | 否 |
| 环境变量和密钥 | `.env*`、`.dev.vars*` | 否 |
| 导出的账本备份 | 浏览器下载目录，或本机 `backups/` | 否 |
| 公开食品与中文译名 | `data/` | 是 |
| 程序、数据库结构、插图 | `app/`、`lib/`、`db/`、`drizzle/`、`public/` | 是 |

刷新、关闭网页、停止服务或更新代码不会删除账本。**不要删除 `.wrangler/`，也不要把整个项目文件夹（含隐藏文件）打包给别人。** 通过 GitHub 分享仓库即可；别人克隆代码不会连接你的电脑或数据库。

在页面“个人资料”中可以导出全部记录与计划，备份内包含个人信息，请妥善保存。该导出不包含开发者批注；如需完整迁移本机数据库（包括批注），停止服务后备份整个 `.wrangler/state/`。当前没有页面导入备份的功能。删除项目文件夹前先备份本机数据库。

本机模式是**一份安装、一个账本**：不同电脑彼此独立，但能够直接操作同一电脑、同一项目目录或操作系统账号的人也可能访问该账本。开发服务只监听回环地址，不作为公网或多人共享服务器使用；不要用 `--host 0.0.0.0` 或网络隧道暴露它。GitHub 仓库公开不会自动部署网站或上传数据。

## 开发与验证

```sh
npm run dev           # 初始化并启动本机开发服务
npm run setup         # 幂等初始化，不覆盖已有配置或数据
npm run test          # 数据规则、账户隔离、计算和分享检查
npm run typecheck
npm run lint
npm run build
npm run check:share   # 检查 Git 暂存区中的待分享文件
npm run test:api      # 已启动本机服务时，创建并清理明确标记的临时测试记录
```

`test:api` 默认使用 3000 端口；设置 `BODY_DASHBOARD_TEST_URL=http://127.0.0.1:3001` 可验证另一份本机安装。测试只清理本次生成的 UUID 和专用标记，不删除普通记录。

代码使用 React、TypeScript、Vinext、SQLite/D1 和公开的 Sites 本机适配插件。数据库迁移只定义结构，不包含个人数据；新增迁移应追加，已应用的迁移不要改写。`AGENT.md` 约定开发和数据规则。

`.openai/hosting.example.json` 仅包含逻辑资源名。初始化会复制为被忽略的本机配置，已有配置不覆盖。本项目保留 Sites 构建能力；将来部署需要部署者自己的项目、账号和访问控制，与运行本机看板是两件事。
